# SERAPH MASTER BRIEF
Date: 2026-09-21
Status: ACTIVE / SOURCE OF TRUTH

## Thesis

SERAPH is an embodied interactive world.

The browser is the runtime, not the product category.

The project explores one central relationship:

human body <-> digital presence <-> material state <-> sound <-> memory <-> space

SERAPH://01 — FALL / ASCENT begins with one humanoid presence that can move between grace, conflict, fall and re-formation.

## Non-goals

SERAPH is not:
- a portfolio animation demo
- a generic three.js character viewer
- a button-driven game prototype
- a literal angel-with-wings versus demon-with-horns costume swap
- a technology checklist

## Core experience law

The person should not feel that they are operating controls.

Their body, stillness, approach, openness, asymmetry and rhythm should become signals the world interprets.

The digital character does not simply mirror the person. It has:
- inertia
- memory
- resistance
- state
- consequence
- recovery

## Flagship experience

SERAPH://01 — FALL / ASCENT

Emotional / material arc:

DORMANT
-> AWAKENING
-> GRACE
-> TENSION
-> FRACTURE
-> FALL
-> AFTERMATH
-> RE-FORM / DEEPER FALL

These are system states, not screens.

## Vertical Slice 01 — THE BODY

The first slice is complete only when a real humanoid presence exists in-browser and can be experienced on a real device.

Required:
- readable humanoid anatomy
- readable face / head silhouette
- real skeleton/rig
- stable idle breathing
- body posture states
- Grace and Fall material states
- state blending, not hard swaps
- camera pose signals driving meaningful body/material responses
- reactive procedural audio
- clean fallback when vision is unavailable
- real-device performance QA

## Long-term medium stack

SERAPH is tool-open.

Candidate materials:
- React / Next.js
- Three.js / React Three Fiber
- GLSL / WebGPU where useful
- skeletal animation / blend shapes
- MediaPipe / computer vision
- Web Audio / spatial audio
- WebSockets / WebRTC
- NFC / RFID
- ESP32 / Arduino-class hardware
- Web Serial / Web Bluetooth
- WebXR
- projection / spatial installation
- local AI / perception when useful

Technology is admitted only when it creates a new human interaction.

## Working method

Every phase must produce:
1. a perceivable experience change
2. reusable system capability
3. real-device proof
4. documentation of what was learned

No phase exists only because a technology is fashionable.
