# SERARA CREATIVE DOCUMENT LAW
Date: 2026-09-21
Status: CANONICAL

For core creative direction, SERARA uses FULL canonical documents.

Do not create:
- v1
- v2
- v3
- pass 01
- pass 02
- final-final naming

Instead:
- create one FULL document
- edit it in place while ACTIVE
- close it only when implementation + real-device QA satisfy its closure gate
- use git history for change history

Engineering phases/slices may still exist for implementation sequencing.
The ban is specifically on fragmenting the canonical creative identity into pseudo-final numbered versions.
